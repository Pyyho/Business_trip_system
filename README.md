# КР №1 — система оформления служебных поездок

Добавлено настольное JavaFX-приложение КР №2 с экранами всех пяти сущностей: [запуск и описание](README-JAVAFX.md). Требуются JDK 21+ и Maven 3.9+. Запуск интерфейса: `mvn javafx:run`.

Консольная версия КР №1 с PostgreSQL, JDBC, многослойной архитектурой и экспортом в Excel `.xlsx` сохранена.

## Предметная модель

В системе реализованы **5 связанных сущностей**:

1. `Employee` — сотрудник.
2. `BusinessTrip` — служебная поездка.
3. `TransportTicket` — транспортный билет.
4. `Accommodation` — проживание в поездке.
5. `TripExpense` — фактический расход.

```text
Employee (1) ------ (N) BusinessTrip
                           |
                           +------ (N) TransportTicket
                           +------ (N) Accommodation
                           +------ (N) TripExpense
```

## Что реализовано

- CRUD для всех пяти сущностей;
- enum `TripStatus`, `TransportType` и `ExpenseCategory`;
- поиск по месту назначения и ФИО сотрудника;
- фильтрация по статусу и диапазону дат;
- сортировка через Collections/Stream API;
- статистика из 9 показателей;
- экспорт всех пяти таблиц в отдельные листы Excel;
- собственные исключения и защита от неверного ввода;
- автоматическое создание схемы БД при запуске.

## Архитектура

```text
Console UI -> Service -> Repository / JDBC -> PostgreSQL
```

- `ui` — меню и ввод;
- `service` — бизнес-правила, статистика и сортировка;
- `repository` — интерфейсы и JDBC-реализации;
- `model` — сущности и enum;
- `util` — подключение, схема и Excel-экспорт;
- `exception` — иерархия собственных исключений.

Полиморфизм и инверсия зависимостей показаны через `CrudRepository<T>`, предметные интерфейсы репозиториев и `DataExporter`.

## Основные бизнес-правила

1. Поездка может ссылаться только на существующего сотрудника.
2. Дата окончания поездки не может быть раньше даты начала.
3. Затраты не могут быть отрицательными.
4. Статусы меняются только по разрешённым переходам.
5. Билеты и проживание оформляются только до начала поездки.
6. Даты билета, проживания и расхода должны входить в период поездки.
7. Номер транспортного билета уникален.
8. Расходы нельзя вносить для запланированной или отменённой поездки.
9. Нельзя удалить сотрудника, пока с ним связаны поездки.
10. Email сотрудника уникален и валиден.

## Запуск

Требуются JDK 21+, Maven 3.9+ и PostgreSQL 12+.

1. Создайте в PostgreSQL базу `business_trips` или запустите готовый контейнер:

   ```powershell
   docker compose up -d
   ```

2. Укажите параметры подключения. В IntelliJ IDEA их можно добавить в **Run → Edit Configurations → Environment variables**:

   ```text
   DB_URL=jdbc:postgresql://localhost:5432/business_trips
   DB_USER=postgres
   DB_PASSWORD=<пароль PostgreSQL>
   ```

3. Для запуска из IntelliJ IDEA откройте `Main.java` и нажмите **Run 'Main.main()'**.

Альтернативно проект можно собрать и запустить из терминала:

```powershell
mvn clean test package
java -jar target/business-trip-system.jar
```

При первом успешном подключении приложение само создаст все необходимые таблицы.

## Демонстрационные данные

При запуске система автоматически добавляет тестовых сотрудников, поездки, билеты, проживание и расходы. Повторные запуски не создают дубликаты.

Автозаполнение можно отключить переменной окружения:

```text
APP_SEED_DEMO=false
```
