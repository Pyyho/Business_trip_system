# КР №2 — настольное приложение «Служебные поездки»

Требуются JDK 21+, Maven 3.9+ и запущенный Docker Desktop.

Из корня проекта:

```powershell
docker compose up -d --wait
mvn test
mvn javafx:run
```

В IntelliJ IDEA выберите Project SDK 21 или новее, перезагрузите Maven-проект и запустите Maven → Plugins → javafx → javafx:run.
Если PowerShell не распознаёт `mvn`, выполните из корня проекта:

```powershell
.\run.ps1
```

Скрипт находит JDK 21+ в `JAVA_HOME`, PATH или установках IntelliJ и Maven из PATH или IntelliJ IDEA. Постоянные настройки системы не меняются. Проверка найденных инструментов: `.\run.ps1 -Check`.
Если выполнение PowerShell-скриптов запрещено, используйте `powershell -ExecutionPolicy Bypass -File .\run.ps1`.

Главный класс графического приложения: `ru.pkc.travel.fx.TravelApplication`.
`ru.pkc.travel.Main` сохраняет консольную версию КР №1.

Настройки JDBC берутся из `src/main/resources/application.properties`.
В текущей Docker-конфигурации PostgreSQL доступен с компьютера по адресу `jdbc:postgresql://localhost:5433/business_trips`.
Проброс порта в `docker-compose.yml`: `5433:5432` — внешний порт `5433`, внутренний порт PostgreSQL `5432`.
После изменения проброса примените конфигурацию командой `docker compose up -d --wait`.
Если сервер отвечает `password authentication failed`, проверьте фактический пароль роли PostgreSQL и `db.password` / `DB_PASSWORD`. Изменение `POSTGRES_PASSWORD` в Compose не меняет пароль в ранее созданной базе: он задаётся при первичной инициализации volume. Не удаляйте volume для исправления пароля, если нужны сохранённые данные.
Переменные окружения `DB_URL`, `DB_USER`, `DB_PASSWORD` имеют приоритет.
Используется база КР №1, SQL выполняют существующие JDBC-репозитории.
При запуске проверяется подключение, создаются отсутствующие таблицы и, если включено заполнение, демонстрационные данные.
Для работы без добавления демонстрационных данных задайте `APP_SEED_DEMO=false`.
При ошибке подключения окно остаётся доступным: исправьте параметры/запустите PostgreSQL и нажмите «Подключиться повторно» (после изменения переменных окружения перезапустите приложение).

## Экраны

Пять вкладок соответствуют пяти сущностям: сотрудники, поездки, билеты, проживание, расходы.
Каждая содержит таблицу, поиск по отображаемым полям, два подписанных фильтра, обновление, добавление, редактирование, удаление с подтверждением и экспорт.
Для поездок и зависимых записей есть включительный фильтр по дате начала/дате записи.
Заголовок столбца переключает направление сортировки; Shift + щелчок добавляет следующий столбец к сортировке.
Экспорт CSV сохраняет текущую отфильтрованную выборку в порядке таблицы. Путь выбирается в FileChooser. Кодировка UTF-8 с BOM, разделитель `;`.

Редактирование открывается кнопкой или двойным щелчком по строке.
Связанные записи выбираются по ФИО/отделу или направлению/сотруднику/датам поездки.
Технические идентификаторы не выводятся. Время билетов вводится в формате `ЧЧ:мм`, даты в формах можно ввести вручную в формате `дд.мм.гггг` или выбрать в календаре, суммы — максимум с двумя знаками после запятой.

Статус поездки меняется отдельной кнопкой. Список содержит только разрешённые переходы.
Новая поездка имеет статус «Запланирована»; детали редактируются только в этом статусе.
Билеты и проживание оформляются до начала поездки. Расходы доступны для согласованной, начатой и завершённой поездки.
При завершении укажите фактическую стоимость; для остальных переходов поле суммы не используется.
Удаление поездки также удаляет связанные билеты, проживание и расходы — это указано в подтверждении.

Вкладка статистики показывает восемь показателей по всей базе: число поездок, запланированные, активные, завершённые, отменённые, плановый бюджет, фактические затраты и среднюю длительность.

## Структура

`src/main/resources/fx/` — FXML главного окна, таблиц, форм и статистики, общий CSS.
`fx/MainController` — навигация, подключение и статистика.
`fx/EntityController` — общие операции таблиц и диалогов.
Для каждой сущности выделены свой пакет JavaFX и отдельный FXML:

| Сущность | Контроллер в `src/main/java/ru/pkc/travel/fx/` | Разметка в `src/main/resources/fx/` |
| --- | --- | --- |
| Сотрудник | `employee/EmployeeController.java` | `employee/employee.fxml` |
| Служебная поездка | `businesstrip/BusinessTripController.java` | `businesstrip/businesstrip.fxml` |
| Транспортный билет | `transportticket/TransportTicketController.java` | `transportticket/transportticket.fxml` |
| Проживание | `accommodation/AccommodationController.java` | `accommodation/accommodation.fxml` |
| Фактический расход | `tripexpense/TripExpenseController.java` | `tripexpense/tripexpense.fxml` |

Контроллер сущности определяет столбцы, фильтры, поля формы и вызовы своего сервиса.
`BusinessTripController` также отвечает за смену статуса поездки и предупреждение об удалении связанных данных.
`fx/EntityScreen` — описание экрана, `fx/EntityReferences` — связанные записи для выбора в формах.
Общие операции таблиц наследуются от `EntityController`; шаблон диалога `form.fxml` и CSS используются всеми сущностями.
Запуск через `run.ps1` остаётся общим для всего приложения.

`fx/FormController` — элементы форм и проверка формата ввода.
`fx/TravelContext` — сборка сервисов и JDBC-репозиториев.
`fx/FxTasks` — выполнение работы с БД в фоновом потоке; обновление интерфейса в JavaFX Application Thread.
`fx/CsvExporter` — CSV-экспорт без зависимости от интерфейса.
Бизнес-правила и доступ к PostgreSQL остаются в пакетах `service` и `repository/jdbc` из КР №1.

`mvn test` запускает тесты сервисов, FXML, фильтрации, сортировки, валидации и экспорта. Для тестов JavaFX нужен рабочий графический сеанс; PostgreSQL им не требуется.

Демонстрационный архив Student Hub в этом репозитории отсутствует. Проверка его backend и JavaFX-клиента через Docker выполняется отдельно по инструкции преподавателя. Собственное приложение работает непосредственно с PostgreSQL через JDBC.

Остановка PostgreSQL без удаления данных:

```powershell
docker compose down
```
